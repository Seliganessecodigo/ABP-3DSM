# 製品バックログ

GreenERのバックログは六つの製品エピックと、技術基盤・品質のエピックで構成されます。各ページで範囲を説明し、受け入れ条件、タスク、依存関係、現在の状態を持つGitHub issueへリンクします。

| エピック | 範囲 |
| --- | --- |
| [EP00 — 技術基盤・品質・開発プロセス](./backlog/ep00) | 技術、アーキテクチャ、データ、セキュリティ、運用、障害処理、アクセシビリティの横断要件をまとめます。子タスクは検証可能な技術成果物であり、完了後も品質要件は継続して適用されます。 |
| [EP01 — アプリケーション一覧](./backlog/ep01) | GreenERが監視するアプリケーションを探して閲覧できます。 |
| [EP02 — アプリケーション監視](./backlog/ep02) | 検出とライフサイクル、定期更新、状態、アプリケーション単位の障害を扱います。 |
| [EP03 — 環境影響の算出](./backlog/ep03) | 追跡可能な根拠、単位、方法、制約とともに算出結果を示します。 |
| [EP04 — 環境ダッシュボード](./backlog/ep04) | 指標を集約し、詳細と履歴を調査できます。 |
| [EP05 — 分析とシミュレーション](./backlog/ep05) | 優先順位付けや比較を支援し、公式結果を変更せずに地域シナリオをプレビューします。 |
| [EP06 — 設定と管理](./backlog/ep06) | 言語、テーマ、認可、監視設定、アカウント管理を扱います。 |

## 製品原則

- 観測値の欠落、エラー、古さを消費ゼロとして扱わない。
- エネルギーとCO₂eの単位、期間、対象範囲、コンテキストを保持する。
- 設定や方法の変更で元の履歴を書き換えない。
- 再計算プレビューは保存せず、公式結果を変更しない。
- 公開参照と管理変更ではアクセス規則が異なり、認可はバックエンドで行う。

## 依存関係と制約

期限の約束ではなく依存順序です：認識・収集 → モデル承認・版付き結果 → 概要・履歴 → 比較・simulation。管理・設定は認可とdesignの依存に従い、Sprint・能力はProjectsで管理します。
