# EP02 — アプリケーション監視

検出とライフサイクル、定期更新、状態、アプリケーション単位の障害を扱います。

[GitHubバックログで開く](https://github.com/Seliganessecodigo/ABP-3DSM/issues/2)

## ユーザーストーリー

| Issue | 機能 |
| --- | --- |
| [US-02 · 検出・削除・復帰](https://github.com/Seliganessecodigo/ABP-3DSM/issues/8) | 検出、確認済み削除、停止、復帰を履歴を失わずに反映する。 |
| [US-03 · アプリケーションの状態](https://github.com/Seliganessecodigo/ABP-3DSM/issues/9) | 稼働中、メトリクスなし、データ古い、削除済みを区別する。 |
| [US-04 · 自動更新](https://github.com/Seliganessecodigo/ABP-3DSM/issues/10) | ページを再読み込みせずに一覧と詳細を更新し、利用者のコンテキストを保つ。 |
| [US-05 · アプリケーションとデータ源の障害](https://github.com/Seliganessecodigo/ABP-3DSM/issues/11) | 障害をアプリケーションやデータ源ごとに分離し、データ欠落をゼロとして扱わない。 |

受け入れ条件、タスク分解、依存関係、状態の正本はリンク先のissueです。このページは製品の範囲を説明し、実装状況を示すものではありません。

[GitHubバックログで開く](https://github.com/orgs/Seliganessecodigo/projects/2/views/1)

## 利用フローと検証基準

| ストーリー | シナリオと期待結果 |
| --- | --- |
| US-02 | 新IDを1回登録。完全で有効な一覧の初回不在で削除確認。復帰時もID・履歴を保持し、欠損を埋めない。 |
| US-03 | 状態・理由・時刻を表示し、可用性・鮮度・計算可否を区別。色だけでなく文字・アイコン。 |
| US-04 | リロードや検索条件・ページ・アプリの喪失なく更新。古い応答で新条件を上書きせず、UIと収集の周期を分離。 |
| US-05 | アプリ・源の障害が他の成功を無効にしない。有効観測を保存し、証拠に基づき復旧。 |

不正応答、timeout、元の障害では削除確認しません。メトリクス404は曖昧です。統合と永続化が前提で、retry・並列数・遅延等には承認方針が必要です。
