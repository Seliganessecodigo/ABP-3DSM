# 方法論とデータ

簡略モデルが観測区間のCPU、メモリ、ディスク、ネットワークからエネルギーを推定します。推定電力を時間に応じてエネルギーへ変換し、地域の炭素強度を掛けて排出量を求めます。係数は学術モデルのもので、電力実測や公式地域係数ではありません。結果は使用した方法論と係数を保持します。

## データを読み取る {#vocabulary}

| 概念 | 意味 |
| --- | --- |
| アプリ | カタログ内で安定した識別情報を持つサービス。 |
| 観測 | ある区間に対応するメトリクスの集合。 |
| エネルギー | 期間内の推定量。単位はkWh。 |
| 炭素強度 | 地域の係数。単位はgCO₂e/kWh。 |
| 排出量 | 単位を明示したCO₂換算量。 |
| カバー率 | 有効な根拠がある期間の割合。 |

## 推定モデル {#model}

| パラメーター | 値 |
| --- | --- |
| CPU (100%) | 100 W |
| メモリ | 0.375 W/GB |
| ディスク | 0.01 W/GB |
| ネットワーク | 0.02 W/GB |

```text
P [W] = P_CPU + P_RAM + P_disk + P_network
E [kWh] = P [W] × Δt [h] / 1000
CO₂e [g] = E [kWh] × I [gCO₂e/kWh]
```

## カバー率を理解する {#coverage}

カバー率は有効な観測で裏付けられる期間の割合です。エネルギーと排出量は別々に計算され、炭素係数がなくてもエネルギー推定が得られる場合があります。期間、単位、カバー率が対応した結果を比較してください。低いカバー率は部分的な分析を示し、消費減少の証明にはなりません。

ゼロは有効な観測がその値を裏付けることを意味します。欠損は利用できるデータがないことで、消費ゼロではありません。更新に失敗すると直前の有効値を元の時刻とともに保持する場合があります。判断前に更新時刻とカバー率を確認してください。画面は各試行後60秒で再照会しますが、毎回新しい測定があるとは限りません。

## 期間と履歴 {#history}

| ルール | 意味 |
| --- | --- |
| 履歴の保持 | 設定変更やプレビューで原本を置き換えません。 |
| 欠損の明示 | 失敗、メトリクス不足、古いデータはゼロと区別します。 |
| 公開参照 | 指標の参照は公開です。設定保存とアカウント管理には権限が必要です。 |

再計算プレビューでアプリと日付を選び、原本を現行モデルと観測地域の現在の炭素係数による推定と比較します。終了日はUTCの一日全体を含みます。上限は30日、10,000観測です。プレビューは保存されず履歴を変更しません。割合の差は単位とカバー率が一致し、原本が正の値の場合に表示します。
