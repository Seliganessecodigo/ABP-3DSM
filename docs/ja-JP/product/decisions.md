# エンジニアリングの原則

エピック、ユーザーストーリー、タスクを検証可能な基準とコード参照で整理しています。Issue、プルリクエスト、コミットが要件・実装・テストを結び、バージョン管理された文書がアーキテクチャ、契約、運用、根拠をまとめています。

## 製品のルール {#rules}

| ルール | 意味 |
| --- | --- |
| 履歴の保持 | 設定変更やプレビューで原本を置き換えません。 |
| 欠損の明示 | 失敗、メトリクス不足、古いデータはゼロと区別します。 |
| 公開参照 | 指標の参照は公開です。設定保存とアカウント管理には権限が必要です。 |

## 統合された機能 {#planned}

アプリケーション比較、環境ランキング、地域シミュレーション、ユーザー・ロール管理、パスワード復旧、監視制御を提供します。JWT認証、Google SSO、TOTPによる二要素認証が管理操作を保護し、環境データの照会は公開されています。

## 推定モデル {#method}

簡略モデルが観測区間のCPU、メモリ、ディスク、ネットワークからエネルギーを推定します。推定電力を時間に応じてエネルギーへ変換し、地域の炭素強度を掛けて排出量を求めます。係数は学術モデルのもので、電力実測や公式地域係数ではありません。結果は使用した方法論と係数を保持します。

## 受け入れ基準 {#acceptance}

画面は指標を期間、単位、カバレッジ、方法論に結び付け、フィルターとナビゲーションの文脈を保持します。読み込み、空、障害、古いデータの状態を明示し、キーボード、見えるフォーカス、色に加えたテキスト、モバイル、テーマ、12言語に対応しています。
