# 製品のビジョンと範囲

GreenERは「どのアプリケーションを監視しているか」「消費量を裏付ける証拠は何か」「推定エネルギーと排出量をどう解釈するか」に答えます。検出、メトリクス、地域情報、履歴を統合し、調査と優先順位付けを支援します。

## 対象者

| 対象者 | 必要なこと |
| --- | --- |
| インフラ管理者 | アプリケーションと環境の変化を把握する。 |
| 運用・環境分析担当 | 期間を調査し、比較可能な結果と欠損を理解する。 |
| 管理運用担当 | 認可と追跡性を保ちながら設定やアクセスを変更する。 |
| 開発・評価チーム | 環境を再現し、受け入れ基準を実証する。 |

これは利用者のニーズであり、確定した権限マトリクスではありません。詳細は[未決事項](./decisions)です。

## 範囲と提供状況

基準：2026年10月15日の`develop`のコード。環境ごとにリビジョンが異なる可能性があり、Issueの完了だけでは本番提供を証明できません。

| 機能 | 文書化された状況 |
| --- | --- |
| 一覧、検索・状態フィルター、画面遷移、8言語 | UIに実装済み。 |
| 検出、ライフサイクルイベント、定期収集、永続化 | バックエンドに実装済み。 |
| 運用状態と収集証拠の参照 | APIで提供。完全なUI表示は別タスク。 |
| 環境ダッシュボード、エネルギー・CO₂e、時系列、ランキング、比較 | 計画範囲。 |
| テーマ、認証、管理、地域シミュレーション、再計算プレビュー | 依存関係のある計画範囲。 |

## 利用の流れと価値

1. アプリケーションを検索して詳細を開き、ID、所在地、状態を確認する。
2. 最後の試行、最後の有効な観測、データ不在を区別して変化を調べる。
3. 計画中の環境分析では期間、カバレッジ、方法論を確認し、同じ条件で比較する。
4. 計画中の管理機能では、過去の結果を書き換えずに許可された設定を変更する。

[利用ガイド](../guide/monitoring)は既存機能、[エピック](../roadmap)は期待する機能を説明します。

## 制約と評価

推定値は直接の電力計測でも、操作による削減効果の因果的な証明でもありません。トランザクション当たりの効率には処理量データが必要です。CSV、列設定、前期間比較はFigmaに存在するだけではMVPに含まれません。地図は任意です。

レビューでは、アプリを見つけられるか、ゼロと欠損を区別できるか、期間・単位・証拠まで追跡できるかを確認します。困難、フィードバック、変更は[#133](https://github.com/Seliganessecodigo/ABP-3DSM/issues/133)と[#134](https://github.com/Seliganessecodigo/ABP-3DSM/issues/134)へ記録します。所要時間、満足度、性能の数値目標には基準値と承認が必要です。
