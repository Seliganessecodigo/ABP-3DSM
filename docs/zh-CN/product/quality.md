# 跨功能要求与验收

[EP00](../backlog/ep00)组织技术基础和质量。RNF持续适用，任务交付有限成果。完成数据库配置不意味着后续不再维护完整性。

## 可观察质量

| 要求 | 证据 |
| --- | --- |
| RNF-01 — 技术 | React/TypeScript与NestJS/TypeScript可构建。 |

| RNF-07 — 体验 | 键盘、焦点、对比度、文字/图标而非仅颜色、响应式、八种语言。 |

权限矩阵、保留期、灾难恢复及可用性/性能数值目标待定。此页不声明SLA或无障碍认证。

## 演示场景

| 给定 / 当 | 预期结果 | 参考 |
| --- | --- | --- |
| 已知应用不在完整有效快照中 | 记录移除并保留历史。 | US-02 |
| 来源故障或载荷无效 | 不确认移除、不制造零值。 | US-02/05 |
| 有效观测后下次尝试失败 | 保留观测并区分新鲜度。 | US-03/04 |
| 有效能源但因子缺失 | 不制造CO₂e、不丢弃能源。 | US-07/08 |
| 请求重算预览 | 原始结果不变，预览不持久化。 | US-12 |
| 无权限的管理操作 | 后端拒绝修改。 | US-18/19/20 |

计划功能必须先实现和测试才能声明交付。

## 就绪、完成与质量门禁

开始前识别成果、使用方、标准、契约和真实依赖。待决系数或权限不能变成技术假设。设计需要状态、导航和可验证交接。

完成要求演示标准、审查代码、测试相关故障、更新契约/文档及证据。创建PR不代表issue完成。Planning、review和feedback归#134。

`develop`的PR需相关检查及SonarQube Cloud：新代码覆盖率≥80%、重复≤3%、评级A、hotspot审查100%。后端可执行行为变更需要测试与LCOV。参见[CI](https://github.com/Seliganessecodigo/ABP-3DSM/blob/develop/.github/quality-gates.md)及[参与贡献](../contributing)。CI不能代替功能验收或可用性评估。
