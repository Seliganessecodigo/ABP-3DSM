# 产品愿景与范围

GreenER回答三个问题：正在监控哪些应用、消耗量有哪些证据支持、如何理解估算能源与排放。发现、指标、区域背景和历史记录用于支持调查与优先级判断。

## 目标读者

| 读者 | 需求 |
| --- | --- |
| 基础设施管理人员 | 识别应用并跟踪环境变化。 |
| 运维与环境分析人员 | 调查时间范围，比较兼容结果，理解数据缺口。 |
| 管理操作人员 | 在授权和可追溯的前提下修改参数与访问权限。 |
| 开发及评估团队 | 重现环境并证明验收标准得到满足。 |

这些是用户需求，不是最终权限矩阵。完整矩阵仍属[待决事项](./decisions)。

## 范围与可用性

文档基准：2026年10月15日的`develop`代码。不同环境可能运行不同版本；关闭issue并不能证明已在生产提供。

| 能力 | 文档中的状态 |
| --- | --- |
| 目录、搜索/状态筛选、导航、八种语言 | 已在界面实现。 |
| 发现、生命周期事件、周期采集、持久化 | 已在后端实现。 |
| 运行状态与采集证据查询 | API已提供；完整界面展示有独立任务。 |
| 环境仪表板、能源/CO₂e、序列、排名、比较 | 计划范围。 |
| 主题、认证、管理、区域模拟、重算预览 | 带有依赖条件的计划范围。 |

## 用户路径与价值

1. 查找应用并打开详情，确认身份、位置及状态。
2. 调查变化，区分最近尝试、最近有效观测与数据缺失。
3. 在计划中的环境分析里选择期间，查看覆盖度和方法，并比较同一范围。
4. 在计划中的管理功能里修改已授权参数，不重写历史结果。

[使用指南](../guide/monitoring)解释现有行为，[史诗任务](../roadmap)描述预期能力。

## 边界与评估

环境估算既非直接电力计量，也不能证明某次操作造成节省。每笔交易效率需要工作量数据。CSV、可配置列及前期比较不会仅因出现在Figma中就自动纳入MVP。地图为可选项。

Review应检查用户能否找到应用、区分零值和缺失、追溯期间/单位/证据。将困难、反馈和改进记录到[#133](https://github.com/Seliganessecodigo/ABP-3DSM/issues/133)和[#134](https://github.com/Seliganessecodigo/ABP-3DSM/issues/134)。耗时、满意度及性能数值目标需要基线和批准，文档不凭空指定目标。
