# EP02 — Application monitoring

Covers discovery and lifecycle, periodic refresh, states, and application-level failures.

[Open in GitHub backlog](https://github.com/Seliganessecodigo/ABP-3DSM/issues/2)

## User stories

| Issue | Capability |
| --- | --- |
| [US-02 · Application discovery, removal, and return](https://github.com/Seliganessecodigo/ABP-3DSM/issues/8) | Reflect discovery, confirmed removal, unavailability, and return without losing history. |
| [US-03 · Application states](https://github.com/Seliganessecodigo/ABP-3DSM/issues/9) | Distinguish availability, missing metrics, stale data, and removal. |
| [US-04 · Automatic refresh](https://github.com/Seliganessecodigo/ABP-3DSM/issues/10) | Keep catalog and detail current without reloading while preserving user context. |
| [US-05 · Application and source failures](https://github.com/Seliganessecodigo/ABP-3DSM/issues/11) | Isolate failures by application and source; never treat missing data as zero. |

Linked issues are the source of truth for acceptance criteria, task breakdown, dependencies, and status. This page describes product scope, not implementation status.
