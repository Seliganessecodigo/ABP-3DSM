# 방법론과 데이터

단순화 모델은 관측 구간의 CPU·메모리·디스크·네트워크로 에너지를 추정합니다. 추정 전력을 시간에 따라 에너지로 변환하고 지역 탄소 집약도를 곱해 배출량을 구합니다. 계수는 학술 모델 값이며 실제 전력 측정이나 공식 지역 계수가 아닙니다. 결과는 원래 사용한 방법론과 계수를 보존합니다.

## 데이터 해석 {#vocabulary}

| 개념 | 의미 |
| --- | --- |
| 애플리케이션 | 카탈로그에 안정된 식별을 가진 서비스. |
| 관측 | 구간에 연결된 지표 집합. |
| 에너지 | 기간의 추정량으로 단위는 kWh. |
| 탄소 집약도 | 지역 계수로 단위는 gCO₂e/kWh. |
| 배출량 | 단위가 명시된 CO₂ 환산량. |
| 커버리지 | 유효 근거가 뒷받침하는 기간 비율. |

## 추정 모델 {#model}

| 매개변수 | 값 |
| --- | --- |
| CPU (100%) | 100 W |
| 메모리 | 0.375 W/GB |
| 디스크 | 0.01 W/GB |
| 네트워크 | 0.02 W/GB |

```text
P [W] = P_CPU + P_RAM + P_disk + P_network
E [kWh] = P [W] × Δt [h] / 1000
CO₂e [g] = E [kWh] × I [gCO₂e/kWh]
```

## 커버리지 이해 {#coverage}

커버리지는 기간 중 유효 관측이 뒷받침하는 비율입니다. 에너지와 배출량은 별도로 계산하므로 배출 계산용 탄소 계수가 없어도 에너지 추정은 있을 수 있습니다. 호환되는 기간·단위·커버리지를 비교하세요. 낮은 커버리지는 부분 분석이며 소비 감소의 증거가 아닙니다.

0은 유효 관측이 그 값을 뒷받침한다는 뜻입니다. 공백은 사용 가능한 데이터가 없다는 뜻이며 소비 0이 아닙니다. 업데이트 실패 시 마지막 유효값과 원래 시간을 유지할 수 있습니다. 의사결정 전 갱신 시각과 커버리지를 확인하세요. 각 시도 후 60초에 화면이 다시 조회하지만 매번 새 측정을 보장하지는 않습니다.

## 기간과 이력 {#history}

| 규칙 | 의미 |
| --- | --- |
| 이력 보존 | 설정 변경과 미리보기는 원본을 대체하지 않습니다. |
| 명확한 누락 | 실패·지표 누락·이전 데이터는 0과 구분합니다. |
| 공개 조회 | 지표 읽기는 공개이며 설정 저장과 계정 관리는 권한이 필요합니다. |

재계산 미리보기에서 앱과 날짜를 선택해 원본을 현재 모델 및 관측 지역의 현재 탄소 계수 추정과 비교합니다. 마지막 날은 UTC 하루 전체를 포함합니다. 최대 30일, 10,000개 관측을 허용합니다. 미리보기는 저장되지 않으며 이력을 바꾸지 않습니다. 백분율 차이는 단위·커버리지가 같고 원본이 양수일 때 표시합니다.

## 실제 데이터에 적용되는 설정 {#personal-preferences}

`/methodology`에서 애플리케이션별 에너지·배출량 한도, 커버리지 기준과 분석 기본값을 설정합니다. 최근 24시간, 7일, 30일, 90일, UTC 기준 이번 달 또는 시작을 포함하고 끝을 제외하는 사용자 지정 기간을 선택할 수 있습니다. 미리보기는 저장 없이 실제 데이터를 읽고 애플리케이션 및 대시보드와 같은 경고 패널을 사용합니다. 저장에는 로그인이 필요하며 자신의 계정에만 적용됩니다. 계산, 이력, 운영 상태는 바뀌지 않습니다. 경고는 화면 필터와 독립적으로 각 한도의 기간을 사용합니다. 분석 기본값은 대시보드와 상세 화면의 URL에 없는 옵션만 채웁니다. 일부 데이터가 한도보다 낮아도 준수를 입증하지는 않습니다. 누락은 절대 0이 아닙니다.
